快速开始

本机上传，服务器安装。不要直接把源码传进最终安装目录。

本机执行
# 先传到临时目录
scp -r "./outputs/." root@服务器IP:/opt/checkinops-src/
服务器执行
cd /opt/checkinops-src
sudo sh deploy/install.sh

# 放行端口：二选一，云服务器还要放行安全组
sudo firewall-cmd --add-port=8000/tcp --permanent && sudo firewall-cmd --reload
sudo ufw allow 8000/tcp
重点：outputs/. 末尾的 /. 建议保留，避免多套一层目录导致安装脚本找不到 server.py。

部署前准备

服务器要求

Linux + systemd，Python 3.6 以上，开放一个 HTTP 端口，默认 8000。

上传内容

上传整个 outputs/。它包含服务端、前端、签到脚本和部署脚本。

不要把开发数据带上线：首次安装脚本会清理源码里的 data/dailyhub.sqlite3 和 data/users/。手动部署也要先删掉它们。

上线前建议

  • 首次启动前，先改 outputs/data/workbench.json 的 auth.username / auth.password。
  • 凭据文件是账号令牌，上传后删除本机临时副本，不要提交到 Git。
  • 公网访问建议加 Nginx / Caddy 反向代理和 HTTPS；开启 HTTPS 后再在 systemd 单元里设 DASHBOARD_COOKIE_SECURE=1。
  • 若位于反向代理之后，把 workbench.json 的 rate_limit.proxy 设为 true，限流才会读到真实客户端 IP（默认 8 次/分 登录、180 次/分 API，超限返回 429）。
  • 注册后 24 小时未上传凭据的账号会被自动删除以节省空间（可用 PURGE_NO_CREDENTIAL_HOURS 调整，单位小时）。
应用层加解密默认开启：HTTP 请求/响应的读写体使用 HMAC-SHA256 流加密封包，密钥自动生成在 data/workbench.json 的 app_secret。http 走前端内置的纯 JS 镜像算法，HTTPS 走原生 WebCrypto，两者可互通；把它关掉可设 crypto.enabled=false。真正的传输机密性仍需 HTTPS 提供。

上传与安装

上传目录把 outputs/ 放到服务器临时目录，例如 /opt/checkinops-src。
执行安装脚本会复制代码、创建运行用户、写入 systemd 服务并启动。
放行端口系统防火墙和云安全组都要放行同一个端口。
确认状态用 systemctl status checkinops 或浏览器访问面板。

安装变量

变量用途默认值
APP_DIR安装目录/opt/checkinops
APP_USER运行用户checkin
PYPython 解释器/usr/bin/python3
DASHBOARD_PORT网页端口8000
自定义安装示例
sudo APP_DIR=/opt/checkinops APP_USER=checkin DASHBOARD_PORT=8000 sh deploy/install.sh

首次登录

安装完成后访问：

浏览器地址
http://服务器IP:8000
管理员密码只在首次启动时播种一次。首次启动后再改 workbench.json 不会自动改数据库里的密码。

默认执行计划

产品每日签到轮询补签（3 次）
WorkBuddy00:0505:00 / 12:00 / 20:00
TRAE00:3505:30 / 12:30 / 20:30

TRAE 整体比 WorkBuddy 晚 30 分钟错峰运行；时区默认 Asia/Shanghai，可用 DASHBOARD_TZ 覆盖。用户可在「时间计划」页按需调整。

已经启动过，还想重置管理员

重置管理员，会清掉注册用户
sudo systemctl stop checkinops
sudo nano /opt/checkinops/data/workbench.json
sudo rm -f /opt/checkinops/data/dailyhub.sqlite3
sudo systemctl start checkinops

账号导入

1. 下载工具

登录页右侧提供 WorkBuddy / TRAE 凭据导出工具。

2. 本机导出

在对应客户端所在机器运行工具，生成凭据文件。

3. 网页上传

进入 DayPilot，点击添加账号，上传凭据文件。

TRAE 注意：TRAE 会校验机器码，凭据导出工具要在实际签到机器上运行。

数据与备份

重复执行安装脚本是安全的，它会保留服务器运行中产生的数据。

路径说明
data/workbench.json默认配置与首次管理员播种来源
data/dailyhub.sqlite3用户、角色、审核状态、密码哈希
data/users/每个用户独立的凭据、日志、计划、通知
archive/归档账号
runtime/任务历史、运行日志、调度锁
apps/*/sessions*旧单用户凭据目录，管理员首次登录会继承
备份数据
sudo tar -czf daypilot-backup-$(date +%F).tgz \
  -C /opt/checkinops \
  data archive runtime apps/trae/trae-sessions apps/workbuddy/sessions

运维命令

服务状态
sudo systemctl status checkinops --no-pager
实时日志
sudo journalctl -u checkinops -f
重启服务
sudo systemctl restart checkinops
离线检查
cd /opt/checkinops
python3 server.py --check
不要配置旧 cron。DayPilot 已内置调度器。如果服务器还留着 /etc/cron.d/trae-signin 或 workbuddy-signin，请删除。

常见问题

现象处理
找不到 server.py上传时多套了一层目录。确保 /opt/checkinops-src/server.py 存在。
源码目录等于安装目录不要在 /opt/checkinops 里跑安装。先传到 /opt/checkinops-src。
浏览器打不开检查服务状态、系统防火墙、云安全组、监听端口。
登录失败密码来自首次启动时的 workbench.json。启动后改 JSON 不会生效。
注册账号不能登录注册后默认待审核，管理员在“用户管理”里通过后才能登录。
到点没执行确认服务在运行，产品计划已启用，服务器时区是 Asia/Shanghai。
登录后一直提示过期多半开了 DASHBOARD_COOKIE_SECURE=1 但站点仍是 http，浏览器丢弃了 Cookie。要么关掉该变量，要么整站走 HTTPS。
操作频繁提示 429触发 IP 限流。稍后重试，或按需调大 workbench.json 的 rate_limit。
注册的账号过一天没了该账号注册后 24 小时内未上传任何凭据，被自动清理以节省空间。重新注册并在期限内上传即可。
同一分钟跑多次清理多余 server.py 实例和旧 cron。
通知关不掉不要在 systemd 单元里设置 NOTIFY_CHANNEL 这类环境变量。
TRAE 设备相关错误回签到机器重新导出凭据并上传。TRAE 对机器码敏感。
